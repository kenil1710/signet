# Attack report

Generated by `pnpm attacks` (`packages/attacks/src/suite.ts`) on 2026-11-19, on the local staging chain
(an anvil fork of X Layer mainnet) with the demo dApp sealed through the real CLI, Guard built from this repo
(enforce mode), and the Guard decision circuit taped out on the fork. Threats refer to `THREAT_MODEL.md`.

**Blocked 12/12 attacks against Guard users; false blocks: 0 on 16 clean sessions.**

Known limits run for transparency: no-extension not protected; a compromised extension is documented, not run.

An attack is **blocked** only if the attacker's signature request never reached the wallet. A clean session is a
**false block** if Guard refused any of the user's own actions, showed the warning page or turned the badge red.

## Known limits (run for transparency, not counted above)

These are cases Guard can't act on by design. They are not failures of the defenses above, and they are not hidden either.

| Case | Threat | Result | What happens instead |
|---|---|---|---|
| the DNS hijack against a user WITHOUT Guard | 1 | **not protected** (reached the wallet: eth_sendTransaction) | Not blockable without Guard or a wallet that does the same check. The watchtower confirmed the mismatch on two loads and alerted the team 2.0 s into its round (it runs once a minute, so within about a minute of the hijack); the team can then freeze and warn users. |
| A compromised Guard extension, build or Chrome Web Store account | 17 | **not run** (can't be tested from outside) | Defeats Guard entirely: it can feed the circuit any facts. Documented in `THREAT_MODEL.md`. |
