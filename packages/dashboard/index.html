02 / How it works

Seal. Approve.
Guard.

Set it up once. After that, every release takes the same path, and your contracts don't change.

01

Every build gets a fingerprint.

Your CI hashes each file and lists the contracts the site may call. That set becomes a release proposal on X Layer.

A stolen CI key can propose a release. It can never approve one.
$ signet seal dist
hashing 7 files…
✓ index.html 9f2c…41aa
✓ assets/app-2aa5a3e0.js 51d0…c3e9
✓ assets/vendor-91c0.js 0be4…77d2
✓ allowlist 3 contracts
✓ origins no change
→ proposed release #43 · tier 00 · code only
02

A TapeOut circuit makes the call.

Approvals and waiting time go into circuit #6, a fixed NAND circuit on X Layer. Riskier changes need more people and a longer wait.

Its beacon has no owner. Nobody can change the rule, including us.
